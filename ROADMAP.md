# ProblemSpot Roadmap

This roadmap communicates direction, not guaranteed dates. Issues and pull
requests remain the source of truth for active work.

## Now: foundation

- Finalize contributor, governance, validation, moderation, and privacy policy.
- Establish continuous integration and branch protections.
- Implement authentication, profiles, categories, and secure database migrations.
- Test Row Level Security before exposing application data.

## Next: report and validate

- Build accessible problem submission, discovery, filtering, and detail pages.
- Add confirmation, support, evidence, following, and progress notifications.
- Implement human review, duplicate merging, status history, disputes, and appeals.
- Pilot the workflow with one focused community.

## Then: open-source missions

- Convert validated problems into contributor-ready mission workspaces.
- Add solution proposals, teams, repositories, issues, milestones, and testing feedback.
- Build contribution profiles and outcome-based recognition.
- Record implementation evidence and distinguish self-reported from reviewed impact.

## Later: optional AI Solution Lab

- Enforce a server-side validated-problem gate.
- Evaluate providers for privacy, licensing, quality, cost, and reproducibility.
- Add reviewed solution briefs, approach exploration, work planning, repository
  assistance, and feedback synthesis.
- Keep all reporting, validation, and manual collaboration independent of AI.

## Definition of meaningful progress

The primary outcome is not total sign-ups or reports. It is the number of
validated community problems that advance into active, accountable solution
work and produce documented outcomes.
